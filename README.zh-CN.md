# SillyTavern ContextCompact

[English](README.md) | **简体中文**

ContextCompact 是一个第三方 [SillyTavern](https://github.com/SillyTavern/SillyTavern) 扩展，可以将较早的聊天轮次压缩为结构化记忆。生成回复时，它用记忆替代已覆盖的聊天历史，并保留近期轮次的原文。已保存的聊天消息不会被删除。

## 功能

- 可以在发送前、完整回复后自动压缩，或只在手动操作时压缩。
- 按完整回复后的上下文窗口比例、token 数，或用户轮次数触发自动压缩。
- 按设置保留近期完整用户轮次的原文。
- 将新达到条件的轮次并入旧记忆，也可以从聊天原文分批重建。
- 以分项或 JSON 形式查看、编辑记忆，并随会话保存。
- 使用当前聊天模型或受支持的 API 连接配置生成摘要。
- 修改压缩提示词和记忆注入提示词，也可以使用本地化默认内容。
- 压缩期间仍可输入文字，但无法发送新消息。
- 提供英文界面和简体中文本地化。

## 安装

### 通过 SillyTavern 安装

1. 打开 SillyTavern 的 **扩展（Extensions）** 面板，选择 **安装扩展（Install Extension）**。
2. 输入本仓库地址：

    ```text
    https://github.com/Atlas4285/SillyTavern-ContextCompact
    ```

3. 完成安装。如果扩展没有立即出现，请刷新 SillyTavern 页面。

请只安装来自可信来源的第三方扩展。

### 手动安装

将仓库克隆到 SillyTavern 的第三方扩展目录：

```bash
cd /path/to/SillyTavern/public/scripts/extensions/third-party
git clone https://github.com/Atlas4285/SillyTavern-ContextCompact.git
```

如果仓库中没有构建好的 `dist/index.js`，先执行：

```bash
cd SillyTavern-ContextCompact
npm install
npm run build
```

然后刷新 SillyTavern。

## 快速开始

1. 打开 **扩展 → ContextCompact**，保持**启用记忆压缩**开启。
2. 选择**压缩时机**和**触发方式**，设置**保留近期原文轮数**，然后点击**保存设置**。
3. 打开一个完整轮次数超过保留轮数的会话。点击**立即压缩**创建第一份记忆，或继续聊天直到自动触发。
4. 在**当前聊天记忆**中查看结果。可直接编辑各字段，或切换到**查看 JSON**，再点击**保存编辑**。

### 主要设置

| 设置 | 含义 | 默认值 |
| --- | --- | --- |
| 压缩时机 | 在发送前、完整回复后检查，或仅按需手动压缩。 | 发送前 |
| 触发方式 | 按上下文窗口比例、完整上下文 token 数或用户轮次触发；每次只使用一种方式。 | 比例，60% |
| 完整上下文 token 阈值 | 选择 token 模式时，完整回复后的上下文达到此值便触发。 | 128,000 |
| 每次压缩轮数 | 选择轮次模式时，上次压缩后达到此用户消息数便触发。 | 1 |
| 保留近期原文轮数 | 将这么多完整轮次保留为原文。 | 10 |
| 记忆目标 token | 要求模型尽量接近此长度；不是输出硬上限。 | 1,000 |
| 摘要语言 | 自动跟随聊天语言，或指定一种语言。 | 自动 |
| 摘要模型 | 使用当前聊天模型或受支持的 API 连接配置。 | 当前聊天模型 |

## 压缩如何工作

一个**轮次**从一条用户消息开始，包含其后直到下一条用户消息前的助手回复和工具调用。ContextCompact 只压缩完整轮次，不会把同一轮拆成记忆和近期原文两部分。

例如，第 1–16 轮已经压缩、第 17–20 轮保留原文时，下次生成收到的顺序是**记忆在前，第 17–20 轮在后**。原始消息仍留在已保存的聊天中。下一次压缩会把旧记忆和新达到条件的轮次一起发送给摘要模型，得到更新后的记忆。

| 时机 | 行为 |
| --- | --- |
| 发送前 | 检查上一轮完整回复后的上下文长度；达到触发条件时，先压缩，再构建下一次请求。 |
| 回复后 | 等整轮回复结束，包括工具调用过程，再检查触发条件并压缩。 |
| 仅手动 | 只在点击**立即压缩**或**从原文重建**时压缩。 |

比例和 token 触发方式计算最后一次请求的输入量**加上该次完整回复**。优先读取 API 的 `prompt_tokens` 和 `completion_tokens`；缺失的部分由 SillyTavern 分词器估算。经过工具调用时，最后一次请求的输入已包含本轮此前的工具过程，不会把各次请求的用量累加。无法确定完整长度时，会跳过这两种自动触发，但仍可手动压缩。按轮次触发则统计上次压缩以来的用户消息数。触发条件不会强行截断一个轮次。

若结果比摘要请求的输入还长，扩展会拒绝它。压缩期间可以继续打字，但必须等操作结束或失败后才能发送新消息。

## 记忆与操作

每个会话在聊天元数据中保存一份当前记忆，包含以下字段：

| 字段 | 含义 |
| --- | --- |
| `currentSituation` | 当前场景或对话状态。 |
| `importantEvents` | 按时间顺序记录的重要事件与决定。 |
| `establishedFacts` | 对话中已经确认的事实。 |
| `relationships` | 相关人物之间的关系及其变化。 |
| `openThreads` | 尚未解决的问题、目标和事件。 |

四个列表字段各用一个可编辑文本框显示，每行一项。**查看 JSON** 可切换到可编辑的 JSON 视图；**保存编辑**会校验并保存任一视图的修改。面板还会显示已覆盖消息数、更新时间、版本和记忆 token 数。

- **刷新**：重新读取已保存的记忆，放弃未保存的编辑。
- **立即压缩**：将新达到条件的完整轮次并入当前记忆。保留的近期轮次之外需要还有更早的轮次。
- **从原文重建**：按连续批次处理原始聊天，替换当前记忆。每批使用上一批得到的临时记忆，近期轮次仍保留原文。
- **清除记忆**：删除当前会话的记忆，不删除聊天消息。重新创建记忆前，后续生成使用原始聊天历史。

按轮次触发时，重建的每批轮数取自**每次压缩轮数**设置。按比例或 token 触发时，每批尽量容纳不超过预估请求预算的完整轮次。如果提供方仍报告上下文过长，扩展会缩小批次重试。若单独一个轮次也放不下，该轮无法压缩。

## 模型与提示词

摘要模型可选择**当前聊天模型**，或 SillyTavern API 连接配置中受支持的配置。当前支持 Chat Completion 和 Text Completion 连接。摘要请求由压缩指令与数据组成；数据包含旧记忆、当前系统提示词或预设内容，以及新达到条件的聊天消息。捕获预设上下文时，会排除旧摘要文字。

两个提示词编辑器都可以使用本地化默认内容，或填写自定义提示词：

- **压缩提示词**：`{{targetTokens}}` 插入记忆目标 token 数；`{{languageInstruction}}` 插入所选摘要语言的指令。
- **记忆注入提示词**：`{{memory}}` 插入已保存的记忆 JSON。未填写该占位符时，JSON 会附加在提示词后面。

后续生成会把记忆作为 system 角色提示词放在剩余原文之前。如果压缩失败，扩展会提示错误，不保存失败结果；生成继续使用原有有效记忆或原始聊天历史。

图片、文件、空消息，或重建时过长的单轮内容，可能使该处之后的原文无法安全压缩。如果已经覆盖的聊天原文被修改，旧记忆会视为过期，需要从原文重建后才能再次替代那部分历史。

## 开发

本扩展使用 TypeScript 编写，并通过 Webpack 打包。在扩展目录中执行：

```bash
npm install
npm run dev               # 监听源码并重新构建
npm run build             # 在 dist/ 生成生产版本
npm run lint              # ESLint 检查
npm run lint:fix          # 自动修复 ESLint 可处理的问题
```

开发监听器只会重新构建 bundle，不会热重载 SillyTavern；修改后请刷新浏览器页面。

### 项目结构

```text
src/
├── index.ts               扩展初始化
├── application/           压缩协调与聊天轮次选择
├── domain/                设置、记忆校验和提示词模板
├── infrastructure/        SillyTavern 对接、摘要请求与聊天存储
└── ui/                    设置与记忆编辑器
i18n/                      简体中文界面文案
dist/                      构建后的扩展 bundle
```

`manifest.json` 声明的生产入口文件为 `dist/index.js`。
